# Модели из Blender

Пилот [#109](https://github.com/Nefeste/pharma/issues/109): даёт ли Blender в фоновом режиме заметно лучший вид машин и
помещений, чем модели кодом из данных (`src/render/machines.ts`). Порядок выбора графики — по уставу
(`docs/11-new-games.md`, «Графика и звук из скриптов»): сначала свой код и скрипты в репозитории. Итог пилота и
сравнение — [`docs/reports/2026-11-blender-pilot.md`](../docs/reports/2026-11-blender-pilot.md).

## Что здесь

| Файл | Что строит |
|---|---|
| `lib.py` | общее: сцена, оси окна, отделка, части с фасками в одном порядке, запечка Cycles, PNG своим кодом |
| `press.py` | роторный таблеточный пресс: части и размеры — из записи `content/equipment/press.yaml`, имена объектов — имена частей; затенение — в `.glb` |
| `room.py` | свет и затенение пола помещения производства (компрессионной) — две картинки PNG |

Сцену для скриптов пишет `tools/blender/scene.ts` — из той же базы и того же кода раскладки, что окно игры: части
записи, отделку `machines.ts`, стены `buildWalls`, светильники `lampPoints`, оборудование по плану. Сам скрипт Blender о
заводе ничего не знает.

## Версия и запуск

- **Blender 5.2.3 LTS**, Linux x64, с blender.org: `blender-5.2.3-linux-x64.tar.xz`, SHA-256
  `78486c018b4443efe5e75ab54c290ed8c15abafd249b862c2c9ce2530a918eec` (сверено со списком сумм на странице выпуска).
  Другая версия — сборка не идёт (`BLENDER` в `tools/blender/scene.ts`).
- Без экрана: `blender --background --factory-startup --python-exit-code 1 --python blender/<скрипт>.py -- <ключи>`.
  В облачном контейнере без видеокарты Blender так и запускается; Cycles считает на процессоре.
- Сборка — одна команда проекта; путь к Blender — `BLENDER`, иначе `blender` из `PATH`:

```bash
npm run models              # сцена → Blender → assets/models: файлы, паспорт sources.json, список окна index.json
npm run models -- --check   # собрать дважды во временные папки, сравнить SHA-256 между собой и с паспортом
npm run models -- --blend   # ещё и .blend сцен в tools/blender/out — открыть в своём Blender (в репозиторий не идут)
```

Сборка — долгая работа (около двух минут на четырёх ядрах), поэтому локально, а не в CI (устав, `docs/04-process.md`).
Тест `tools/test/blender.test.ts` проверяет, что файлы — те, что в паспорте, а паспорт — от нынешних записи, раскладки и
скриптов: запись пресса или план помещения изменились — тест просит перестроить модели.

## Повторяемость

Файлы повторяются байт в байт: два прогона подряд и прогон в один поток (`-t 1`) дают те же SHA-256. Что для этого
сделано — в `lib.py`: пустая сцена фабричных настроек, у Cycles одно зерно и ровное число проб без подстройки и
шумодава; деталь строится в своей сетке и переносится в сетку части в одном порядке (фаска Blender отдаёт вершины в
порядке адресов памяти — без этого `.glb` менялся от прогона к прогону); картинки запечки пишет свой код (zlib,
уровень 9), а экспорт glTF кладёт в `.glb` байты этого файла как есть. На другом процессоре Cycles может дать другой
младший бит у части точек — тогда меняется только картинка запечки, а паспорт обновляет `npm run models`.
