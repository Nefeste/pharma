# Модель данных

**Состояние:** проект, кода ещё нет. Поля и имена уточнит прототип. Здесь — какие записи есть
в базе игры (`content/`), какие сущности живут в состоянии движка, как связаны и через какие
статусы проходят. Устройство движка — [`02-architecture.md`](02-architecture.md); почему так
делится «сущность / счётчик / картинка» — ADR [0003](adr/0003-hybrid-simulation.md).

## 1. Два мира

| | База игры (`content/`) | Состояние завода (`PlantState`) |
|---|---|---|
| Что | **что бывает**: материалы, оборудование, карты, продукты, роли, причины, поставщики, покупатели, профиль | **что есть сейчас**: партии, паллеты, серии, люди, заказы, отклонения, деньги |
| Кто пишет | авторы контента, с источниками и `review` | движок, командами и временем |
| Идентификаторы | вечные строки: `mat.api.paracetamol` | буква вида и номер по порядку: `L1207` — партия, `U77` — паллета |
| Меняется | новой версией записи | каждым событием |

## 2. Единицы

Всё в состоянии — **целые числа** (ADR студии 0004, [`02-architecture.md`](02-architecture.md), §4).

| Величина | Единица в движке | В записи `content/` пишется |
|---|---|---|
| Масса | миллиграмм | `250kg`, `30g`, `500mg` |
| Штуки | штука | `200000` |
| Время | секунда | `45m`, `6h`, `72h`, `3d` |
| Деньги | копейка | `1250.50` (в валюте записи) |
| Доли | сотая доля процента (1 = 0,01 %) | `98.5%` |
| Температура | десятая доля градуса | `25C` |
| Длина и клетки | сантиметр; клетка — 100 см | `1.2m` |
| Скорость | дробь `числитель/знаменатель` | `120000/h`, `200/min` |

Сборщик базы переводит записи в единицы движка и падает на неизвестной единице.

## 3. Записи базы

| Вид | Папка | Что в записи |
|---|---|---|
| Материал | `materials/` | вид (`api`, `excipient`, `packaging`, `consumable`), имя, МНН, единица учёта, условия хранения, срок годности или повторных испытаний, пересчёт на содержание, тара, план отбора проб, спецификация |
| Тара | `containers/` | бочка 50 кг, мешок 25 кг, рулон, коробка, контейнер; размеры и модель на паллете |
| Грузовая единица | `units/` | паллета (европаллета 1200 × 800, пластиковая), гофроящик (размеры), схемы укладки |
| Поставщик | `suppliers/` | страна, валюта, материалы с ценой, минимальной партией и сроком, надёжность, качество, условия оплаты |
| Помещение | `rooms/` | тип, класс, наименьшая площадь, нужные предметы, воздух, двери, образцы обстановки S/M/L |
| План завода | `plants/` | в прототипе: здание в клетках 1 × 1 м; помещения — тип, класс, прямоугольник со стенами по краю, пускают ли технику, рабочая точка; двери — клетка, длина и направление вдоль стены, вид (дверь, двойная, ворота, рампа, окно передачи), только для материалов; зоны с местами сеткой; стеллажи — ряды секций и сторона прохода; оборудование и машины линии — точка и поворот; рампы, стоянка техники, вход; посты ожидания по ролям (с 3а); приборы лаборатории; энергия — вентиляция по классу и постоянная база |
| Оборудование | `equipment/` | класс, модель, поставщик, площадь, помещения, производительность, люди, сети, уборки, узлы и износ, отказы, калибровки, модель кодом; в прототипе узлы — ресурс, таблица отказов от износа, разброс МОК, запчасть, время замены и ремонта, размер следа на полу (`size`), модель кодом из частей (`model`, только для окна); у машин линии (`machines/`) — ещё рост микроостановок и заминки |
| Запчасть | `spares/` | поставщик, цена, срок поставки, неснижаемый и начальный уровни склада ЗИП |
| Техника | `vehicles/` | груз, подъём, скорость, проезд, аккумулятор, допуск |
| Технологическая карта | `recipes/` | продукт, форма, размер серии, состав, стадии и операции, режимы, МОК, выход |
| Продукт и товарная позиция | `products/` | МНН, форма, дозировка; позиции: упаковка, состав упаковки, схема ящика и паллеты, срок годности, группа рынка, ЖНВЛП; в прототипе позиции — `skus/` с ценой завода и зарегистрированной предельной ценой |
| Спецификация | `specs/` | показатели и пределы для материала, балка, готовой продукции, стабильности |
| Методика | `tests/` | испытание: прибор, работа аналитика, работа прибора, ночью сам или нет, расходники, погрешность |
| Причина | `causes/` | что меняет в показателях, априорный вес, улики и их правдоподобие по шагам расследования |
| Матрица уборок | `cleaning/` | переходы между продуктами и вид уборки |
| Роль | `roles/` | отдел, допуски, процедуры, зарплата относительно рынка |
| Процедура (SOP) | `sops/` | что регулирует, для каких ролей, время обучения |
| Рынок | `markets/` | группы, сезонность, база спроса, эластичность, конкуренты |
| Покупатель | `customers/` | вид, оплата, требования, поведение заказов; в прототипе — отсрочка, дни и час заказа, через сколько дней срок, наименьший остаточный срок годности, спрос по позициям в пачках в сутки |
| Событие | `events/` | внешние события: условия, шанс, сигнал заранее, последствия |
| Проект | `projects/` | этапы, цены, люди, сроки, шанс |
| Регуляторный профиль | `profiles/` | проверки, маркировка и плата за коды, цены, налоги и сроки их уплаты, праздники, труд (ночные часы, взносы), расчёты за энергию, ключевая ставка, валюта (ADR [0004](adr/0004-regulatory-profile.md)) |
| Сценарий | `scenarios/` | участок и завод на старте, дата, деньги и кредитная линия, цена энергии, покупатели, рынок, цели, письма |
| Справочник | `encyclopedia/` | статьи справочника технолога с источниками |

Все записи с фактами о настоящем производстве несут `source` (список источников из
[`10-domain.md`](10-domain.md) или своих) и `review: draft | checked`. `checked` ставит
только человек (устав, ADR 0012).

```yaml
id: cause.press.tooling

  - { attr: hardness, coef: -0.08 }
  - { attr: friability, coef: 0.002 }
# дальше — для расследования (часть 4)

evidence:
  - { step: step.maintLog, shows: tooling-over-life, p: 0.9, else: 0.05 }
  - { step: step.inspect, shows: worn-edges, p: 0.95, else: 0.02 }
  - { step: step.compare, shows: same-press, p: 0.8, else: 0.3 }
capa: [capa.replace.tooling, capa.pm.tooling]
source: [textbook-tech]

```

## 5. Технологическая карта: устройство

Карта устроена по мотивам ISA-88 ([`10-domain.md`](10-domain.md), §7), но проще:

```
карта (recipe) ─ продукт, размер серии, состав, выход
 └─ стадия (stage) ─ тип помещения, класс оборудования, загрузки, люди
     ├─ режимы (params): цель и диапазон
     ├─ длительность (time): подготовка, на загрузку, по скорости, разброс
     ├─ МОК (ipc): испытание, частота, пределы
     └─ уборка после — по матрице уборок
```

Упаковка — своя карта у товарной позиции: формат линии, состав упаковки, схема ящика и
паллеты, печать переменных данных, маркировка.

## 6. Сущности состояния

| Сущность | Ключевые поля |
|---|---|
| `Lot` — партия материала | материал, поставщик и изготовитель, номер изготовителя, внутренний номер, количество, срок, паспорт (записанные свойства), истинные свойства (видит только движок), статус, тары |
| `Container` — тара | партия, количество, где лежит (паллета или место), вскрыта или нет |
| `Unit` — паллета или гофроящик | вид, SSCC, где стоит, что на ней (тары, ящики), статус ярлыка |
| `Location` — место | адрес, зона, ярус, допустимый вес, условия |
| `Batch` — серия | продукт, карта, номер серии, размер, этап, операции, досье, истинные показатели и причины, результаты испытаний, отклонения, статус выпуска; время с задания до выпуска по состояниям: ждёт даты, материалов, людей, помещения, уборки, оборудования, ремонта, лаборатории, линии, решения — или работает |
| `Op` — операция серии | стадия, помещение, оборудование, люди, начало и конец, режимы, МОК, выход |
| `Machine` — оборудование | модель, место, состояние, чистота и её срок, узлы с износом, квалификация, калибровки |
| `Line` — линия | машины по порядку, накопители, формат, серия, счётчики, коды |
| `Case` — гофроящик ГП | в прототипе — тара партии ГП: пачки, диапазоны кодов, паллета, когда уложен; SSCC окно строит из номера тары; выбракованные коды — у задания на упаковку серии |
| `Person` — человек | роль, навык, черты, допуски, график, усталость, настроение, задача сейчас; без задачи — путь на пост или к выходу: откуда и с какого мгновения (с 3а) |
| `Task` — задача | вид, кто, техника, откуда, куда, начало и конец, приоритет |
| Фура | рампа, заказ поставщика или покупатель, паллеты на ней, когда пришла, встала ли к рампе, открыт ли кузов (с 3а: фура поставщика — после проверки у рампы) |
| `Sample`, `Test` | что, откуда, методика, прибор, аналитик, результат, проверка |
| `Deviation` | откуда, класс, серии и партии, срок, расследование, CAPA, статус |
| `Probe` — расследование | отклонение, шаги, улики, версии, вывод |
| `Order`, `Po`, `Shipment` | покупатель или поставщик, позиции, даты, статус, деньги. В прототипе заказ покупателя — строки (ящиков заказано, в резерве, отгружено), срок, наименьший остаточный срок, зарезервированные ящики, паллеты заказа; отгрузка — ящики с отрезками кодов, сведения в систему мониторинга и подтверждение покупателя, сумма и НДС |
| `Tender`, `Contract` | условия, график, гарантия, штрафы |
| `Project` | вид, этапы, люди, траты, шанс |
| `Cash` — касса | остаток, проводки (момент, сумма, статья, ссылка), счета к получению и к оплате со сроком, НДС квартала, энергия месяца, выплаты людям с начала года |
| `Part` — узел | машина, наработка с установки, запас до отказа (знает только движок), исправен или отказал, замена по плану, задача ремонта |
| Склад ЗИП, заказ запчасти | запчасть: на складе и в резерве; заказ: сколько, когда придёт, сумма, НДС, предоплата |
| Журнал оборудования | момент, машина, узел, отказ · ремонт · замена, износ, серия, люди (GMP ЕАЭС, ч. I, п. 4.31) |
| Потери за сутки | по участкам: задержки задач по причинам (люди заняты, людей нет в смене, техника, прибор, место), ожидание фуры во дворе — рампа занята (с 3а), транспортировка (с грузом и порожняком), перемещения пешком — и с задачей, и на пост (с 3а); дефекты; уборки после просроченной чистоты |
| `ShiftTask` — сменное задание | линия, смена, начало и конец, задание и выпуск в годных пачках |

**Партия материала:**

```
ожидается → карантин → пробы отобраны → на испытаниях → разрешено → (израсходовано)
                                                     ↘ отклонено → возврат / уничтожение
разрешено → заблокировано (расследование, срок, хранение) → разрешено | отклонено
разрешено → повторные испытания (дата подошла) → разрешено | отклонено
```

**Серия:**

```
запланирована → задание выдано → в работе (по стадиям) → балк в карантине → балк разрешён
  → упаковка → ГП в карантине → проверка досье → выпущена → (отгружена частями)
любой этап → держать (отклонение) → дальше | отклонена
выпущена → отзыв (часть или вся)
```

**Готовая продукция:** карантин ГП → выпущена (решение уполномоченного лица) → в обороте (сведения о серии
опубликованы в АИС Росздравнадзора) → отгружена ящиками | отклонена.

**Заказ покупателя:** открыт → отгружен в срок полностью | недопоставка (закрыт неполным) | опоздал (отгружен позже
срока).

**Машина:** работает · ждёт · переналадка · уборка · микроостановка · авария · ППР ·
калибровка · квалификация · не используется. Отдельно — **чистота**: чистая до … · грязная,
убрать до … · занята серией.

**Узел:** исправен → отказал (машина стоит) → ремонт: ждёт слесаря или запчасть → исправен, новый · исправен → замена
по плану, как только машина свободна → исправен, новый.

**Отклонение:** открыто → классифицировано → расследуется → CAPA назначено → закрыто →
(через 3 месяца) эффективность подтверждена | повтор.

Переходы, которых нет на схемах, движок не делает. Это инвариант в тестах
([`02-architecture.md`](02-architecture.md), §15).

## 8. Прослеживаемость

- **Назад:** пачка (код) → ящик (диапазон) → серия → досье: стадии, оборудование, люди,
  помещения → партии сырья и упаковки → поставщики и паспорта.
- **Вперёд:** партия сырья → серии, где она израсходована → ящики → паллеты → отгрузки →
  покупатели.
- Архив хранит связи закрытых серий и отгрузок компактными таблицами
  ([`02-architecture.md`](02-architecture.md), §13). Прослеживаемость работает за все годы
  партии.

## 9. Номера

- **Внутренний номер партии:** `П-ГГММ-NNNN`.
- **Номер серии:** `ГГММNN` (год, месяц, порядковый).
- **SSCC:** 18 цифр по правилам GS1 с вымышленным префиксом компании.
- **Код маркировки:** GTIN + серийный номер + контрольная часть.

Формат серийного номера и контрольной части — условный и похожий на настоящий, без
настоящих ключей ([`10-domain.md`](10-domain.md), §3).
